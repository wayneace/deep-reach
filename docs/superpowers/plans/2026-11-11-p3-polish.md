# P3 收尾计划（v0.11.1）

> 日期：2026-11-11
> 分支：`fix/p3-polish`
> 前置：v0.11.0 已发布；以下三项来自最终审查的 deferred minors。

## 目标

1. **bsk-only 渠道状态准确**：x / reddit / xiaohongshu / zhihu / douyin 在 bsk 已安装时显示 `fallback`，不再误报 `needs_setup`；bsk 未安装时仍为 `needs_setup`。
2. **移除未生效的 `browser.bsk_profile`**：bsk 始终使用当前已连接的浏览器 profile；文档不再承诺 `main | dedicated` 配置。
3. **高风险门覆盖 backend risk**：`risk.allow_high` 和 stderr 警告使用 action 与 backend 的最高风险，而不只看 `action.risk`。

## 非目标

- 不实现 bsk 专用 profile 启动。
- 不新增 bsk 站点 recipe。
- 不改 `NEED_UI` 的 handoff 语义。
- 不发布 v0.11.1（除非用户明确要求）。

## Task 1：bsk-only 状态

**RED**

- `Environment` 增加 `bsk_installed`，默认 `False`。
- 增加 bsk-only 渠道测试：
  - bsk 已安装 → `fallback`，`runnable=True`，`ui_fallback_actions` 包含全部动作。
  - bsk 未安装 → `needs_setup`，`runnable=False`。
- `next_action_for(status="fallback")` 返回 bsk 引导。
- doctor summary 增加 `fallback` 计数。

**GREEN**

- `detect_environment` / `environment_from_profile` 探测 bsk。
- `channel_availability` 识别 bsk-only 渠道。
- `doctor` / `channels` 文本与 JSON 显示 `fallback`。
- 更新 README 状态列表和 PRODUCT 状态说明。

## Task 2：移除 `bsk_profile`

**RED**

- `keys.example.yaml` 不再包含 `browser.bsk_profile`。
- doctor 的 `bsk.profile` 固定为 `current`。
- `NEED_UI` 的 `meta.profile` 固定为 `current`。
- 更新相关测试与文档断言。

**GREEN**

- 删除 `keys.get("browser.bsk_profile")` 读取。
- `_bsk_hint` 使用“当前浏览器 profile”。
- README 配置片段删除 `bsk_profile`，并说明用 bsk 自己的 `--browser` 选择实例。
- 更新 `keys.example.yaml` 注释。

## Task 3：有效风险

**RED**

- `action_risk()` 测试：action risk 与 backend risk 取最高。
- dispatch 测试：action risk 为空、backend risk=high 时，`risk.allow_high=false` 返回 `POLICY_BLOCKED`，默认发出警告。
- CLI/doctor action 详情显示 backend risk。

**GREEN**

- `action_risk()` 加入 availability；`channel_risk()` 复用它。
- dispatch 的高风险门、警告、`NEED_UI` meta 使用 `action_risk()`。
- CLI/doctor 的 action risk 显示同步。

## Task 4：验证与收尾

- 版本升到 `0.11.1`，更新 CHANGELOG。
- `uv run pytest -q`
- `uv run ruff check .`
- `uv build --wheel && uv run python scripts/check_wheel.py`
- 手动 smoke：`channels --json`、`doctor`。
- 独立审查后提交；未获用户同意不推送、不合并、不打 tag。
